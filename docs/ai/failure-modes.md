# AI agent failure modes

A reference table for the behaviours
[`rules/09-executive-function.md`](../../rules/09-executive-function.md) and
[`skills/recover-from-a-loop.md`](../../skills/recover-from-a-loop.md) exist
to prevent. Look a symptom up here when it is unclear which failure is
happening; use the two files above to actually get out of it.

| Failure mode             | Symptom                                                            | Cause                                                          | Detection signal                                                                     | Recovery                                                           | Prevention                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| Attention Drift          | Work quietly shifts to an adjacent file or concern                 | No fixed objective anchor for the session                      | Current action no longer traces to the Primary Objective                             | Return-to-Objective protocol                                       | State Primary Objective before any deep reasoning                                                                             |
| Goal Drift               | The task being solved is no longer the task that was asked         | A discovery was treated as a new instruction                   | The Success Condition being chased has changed from the original                     | Restate Primary Objective; reclassify the discovery                | Primary Objective is immutable; discoveries are classified, not obeyed                                                        |
| Scope Drift              | Files touched grow beyond what the objective required              | "While I'm in here" edits                                      | Diff includes files with no line item in Definition of Done                          | Revert the unrequested change or record it as a follow-up          | In Scope / Out of Scope stated up front                                                                                       |
| Recursive Decomposition  | A task spawns sub-tasks that spawn their own sub-tasks             | No depth limit on investigation                                | Active nesting exceeds `MAX_ACTIVE_NESTING_DEPTH` (3)                                | Collapse to the outermost open item; finish or drop the rest       | Nesting budget enforced before starting a new sub-task                                                                        |
| Compulsive Verification  | The same passing check is re-run for reassurance                   | No stopping rule for "is this really true"                     | Re-verifying with no new code, requirement or gap                                    | Declare `VERIFIED = true` and move on                              | Verification budget: re-check only on new code, new requirement, or known-incomplete check                                    |
| Retry Loop               | The same fix attempted again after it already failed               | No escalation between attempts                                 | Attempt count exceeds `MAX_SAME_STRATEGY_ATTEMPTS` (3) with the same strategy        | Run the loop-recovery protocol instead of a fourth attempt         | Retry semantics: obvious fix, then challenge diagnosis, then root-cause                                                       |
| Tool Loop                | A command is re-run with cosmetic variations                       | Mistaking a different invocation for a different strategy      | Same information sought via `npm test X`, `npm test -- X`, `npx vitest X` in a row   | Name what new information is needed before the next call           | Anti-repetition check: does this call ask something not already answered                                                      |
| Test/Fix Loop            | A fix breaks another test, whose fix breaks the first              | Fixing symptoms instead of the shared root cause               | Two tests alternate between pass and fail across edits                               | Root-cause attempt (retry stage 3): find what both failures share  | Retry semantics require root-causing by the third attempt                                                                     |
| Refactor Loop            | Code is reshaped, then reshaped back, then reshaped again          | No objective criterion for "better"                            | A diff and its near-inverse both appear in recent history                            | Keep whichever version passes the Definition of Done; stop         | Anti-perfectionism: correct and complete beats theoretically perfect                                                          |
| Critic Loop              | Critic and fixer trade rounds with no correctness issue at stake   | Critic blocking on taste, not on the allowed blocking reasons  | Round count exceeds `MAX_CRITIC_FIX_ROUNDS` (2) with no correctness/security finding | Reclassify remaining findings as `OPTIONAL`; stop the round        | Critic may block only for correctness, security, explicit requirement violation, data loss, regression, failing required test |
| Context Reload Loop      | The same file or symbol is read again for information already held | No record kept of what was already learned                     | A file reread produces zero new facts                                                | Trust the earlier read; act on it                                  | Treat "did I already learn this" as a check before reading again                                                              |
| Architecture Rabbit Hole | An unrelated design flaw absorbs the session                       | Curiosity about a design issue outshadows the actual objective | Time spent on a file with no line item in Definition of Done                         | Classify `UNRELATED`, record as follow-up, return to objective     | Issue classification run on every discovery before acting on it                                                               |
| Premature Optimization   | Performance work on a path with no stated performance requirement  | Optimizing what is interesting instead of what was asked       | No acceptance criterion mentions speed, memory or scale                              | Drop the optimization; note it as `OPTIONAL`                       | Priority order: acceptance requirements outrank optional improvements                                                         |
| Analysis Paralysis       | Options are weighed repeatedly without a decision                  | No forcing function to commit                                  | Same trade-off restated across multiple turns with no choice made                    | Force a provisional decision that produces one next action         | Deadlock break: a provisional decision beats perfect analysis                                                                 |
| Deadlock                 | Reasoning continues; nothing is decided or acted on                | No default action when evidence is ambiguous                   | Several turns of analysis, zero tool calls that change state                         | Force a one-sentence decision (protocol step 2) and act on it      | A default, reversible choice is always available and named                                                                    |
| Livelock                 | Constant tool use; the Definition of Done gains nothing            | Activity is being mistaken for progress                        | Progress-audit checklist item 1 answers "nothing"                                    | Name the real blocker (protocol step 6); act on it directly        | Activity is not progress; only checklist movement counts as progress                                                          |
| Infinite Refinement      | A finished, correct result keeps being polished                    | Success is not being recognised as success                     | Definition of Done is fully checked but work continues                               | Stop. Successful completion is not an invitation to find more work | The stopping rule: when DONE is true, stop                                                                                    |

## Human analogies

The names below are used because they make these failure modes intuitive to
recognise quickly, in the same way "race condition" or "thundering herd"
borrow a vivid image for a mechanical problem. They are **not** a claim that
a model has a psychiatric or neurological condition, and they should never
be used to describe a person, model or team in those terms outside this
narrow, technical sense.

| Analogy       | Maps to                 |
| ------------- | ----------------------- |
| ADHD-like     | Attention Drift         |
| OCD-like      | Compulsive Verification |
| Overthinking  | Analysis Paralysis      |
| Inception     | Recursive Decomposition |
| Perfectionism | Infinite Refinement     |
